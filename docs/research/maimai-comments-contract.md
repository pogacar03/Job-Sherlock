# 脉脉职言评论结构核查

日期：2026-11-16（上海）。状态：**limited**。仅做只读页面探测，没有发帖、点赞或使用私有接口。

`opencli doctor` 显示 CLI 2.0.3、扩展 1.0.27 已连接；这不证明每个页面的登录状态或读取稳定。

本次最多探测两条此前已知的职言原帖。第一条实际跳转到浏览器错误页，显示 DNS 解析失败，不能作为无评论的证据。第二条原帖正文可见，页面显示未登录，能够看到一批评论以及“查看全部回复”的入口。

该页中观察到普通评论位于 `main [data-sentry-component="CommentList"]` 下的 `[data-sentry-component="CommentCard"]`；评论文本在卡片下的 `[data-rich-text]`。存在单独的作者、日期及回复入口，但本次未充分验证父回复与作者字段的对应关系。页面还有 AI 回复与其他区域，不能仅凭通用富文本选择器将其一并作为普通评论。

目前没有可靠确认**空评论、加载中、折叠回复和推荐区**的全部页面状态，也没有在第二种可读正文布局上验证同样的结构。故现阶段无法安全声明评论解析契约完整；保留脉脉评论 `not_supported`，不把当前页的可见条数当作全部评论，也不将测试帖子归因于目标团队。

本记录只保存去标识化的结构信息；没有收录评论原文、用户信息、浏览器会话或帖子链接。后续需要在能区分空状态与加载中，并验证回复层级后，再按 B5 引入有界可见评论读取。

后续第三次只读探测中，另一篇页面同样出现 CommentList / CommentCard，但可见区包含对平台 AI 的提问及其回复；这进一步说明普通员工体验与 AI 文字需要区分。该页面仍不能确认空状态和折叠回复契约，结论保持 limited。

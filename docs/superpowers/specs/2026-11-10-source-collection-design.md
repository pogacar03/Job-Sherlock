# 根据真实 Sherlock 修正采集架构

用户确认参考仓库为 `sherlock-project/sherlock`，并指出此前只修README不足以纠正代码方向。本次按已授权的开发请求直接实现，不重复进行需求访谈。

## 本次决策

Sherlock是用户名跨站存在性查询工具。可借鉴本地可维护的站点注册表、并发请求和结构化状态，不能将其账号存在性判定移植为企业体验判断。本项目保留已有证据契约，新增可配置的公开原文采集模块，补全“搜到URL → 抓取原文 → 审阅 → 导入”的实际代码路径。

首版已经存在的人工导入和离线演示继续可用；本次新版本为0.2.0，仍使用Python3.11+标准库。没有提供跨平台登录会话、验证码绕过或搜索服务API。搜索线索仍由宿主工具发现，但计划新增按来源域名生成的检索式。

## 输入、采集和状态

`sources`列出本地JSON来源注册表；`plan --sources FILE --source ID`使用指定注册表生成来源检索式。注册表配置id、名称、域名、公开抓取/人工读取方式、检索模板、登录/验证码/删除页面标题特征；默认配置随包发布，不在运行时下载可变远程清单。

`collect CASE --urls FILE --sources FILE --workers 4 --timeout 10`接受已找到的原文URL数组，单批最多100个，去掉跟踪参数与片段后合并重复，线程池最大16。请求仅GET，公开地址解析后固定IP连接并逐跳检查；阻止凭据URL、非HTTP(S)、内网地址及跳转到内网。超时为连接/读取预算，DNS解析仍由系统完成，不承诺系统DNS调用的硬实时取消。默认正文上限1MB。

状态区分retrieved、manual_required、blocked、login_required、rate_limited、not_found、http_error、timeout、network_error、unsupported_content、empty、too_large、unsafe_url和redirect_limit。HTTP200登录壳或验证码不算原文成功；HTTP403/429/5xx不能变成“没有关于这家公司的信息”。不重试不明访问失败，不执行网页脚本。

## 输出和审阅

每次采集保存到案例的 `collections/<时间戳-随机ID>/`，含注册表快照、`run.json`、非可执行扩展名的响应快照及 `evidence-drafts.json`。run记录原始URL、最终URL、来源、HTTP码、耗时、状态、标题、可见文本、内容SHA256及目标词提及情况。正文是基本HTML/纯文本提取，不宣称是语义清洗后的文章正文。

草稿只包含已抓取的信息；公司/部门/岗位/观察日期/来源类型/结论均不根据请求目标自动补齐，缺失值留null。草稿直接导入必须失败；审阅者确认归属、逐字摘录与观察后再调用已有import。任何采集成功都不自动增加证据数量或来源簇。

报告新增独立采集概况，展示尝试、访问受限与其他错误；和已审阅证据分开展示，避免“没采到”和“没有相关情况”混淆。报告中不得执行或直接嵌入未转义的远端内容。

## 验收

测试来源配置、模板转义和域名匹配；真实执行并发队列；HTTP错误/200软错误/超时正确分类；私网和恶意跳转拒绝；快照与哈希可复查；草稿不得自动晋升；旧流程24项测试保持通过；真实公开页面做一次只读采集验证，明确不代表对该实体完成背调。
